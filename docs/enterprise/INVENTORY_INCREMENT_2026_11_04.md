# Internal campaign inventory increment

This is an implementation increment for review, not a v1.2.5 release or an instruction to enable sales. The Portal feature-readiness flag remains unchanged.

Implemented: independent category/material catalogue, material units and reorder thresholds; stock receipts and signed quantity adjustments; immutable movement records with actor, reason, resulting balance and unique request references; office-to-office distribution requests, audited pending cancellation and atomic fulfilment; scoped stock/history views; low-stock dashboard alerts; CSV stock statements with spreadsheet formula escaping. Campaign offices are represented by existing polling-unit locations, which preserves the application's existing user and installation geographic boundaries. Searchable office selection returns only permitted locations. Existing commercial Product/Order data is not reused.

Installation entitlement and explicit capabilities are checked at routes and again at the service mutation boundary. Geographic rank alone supplies no inventory permission. Scope queries use PollingUnit Eloquent relations before constructing subqueries, preserving ward/LGA/state and licensed boundaries. Distribution requires authority over both source and destination. Granting `merchandise.orders.view` permits request creation; fulfilment separately requires `merchandise.orders.fulfil`.

Every stock mutation runs in a transaction using locked balance rows. Transfers acquire offices in numeric order. Fulfilment locks the request and is idempotent; adjustments require a unique UUID and reject altered retries. Insufficient stock rolls back both stock rows and audit inserts. New transactional tables explicitly use InnoDB and avoid foreign keys into potentially MyISAM legacy geography/user tables. No delete or edit endpoint can rewrite stock history. Migration rollback deliberately retains inventory and history.

Validation: local PHP 8.4 syntax checks and 29 application tests (70 assertions) pass on SQLite and MariaDB 11.8.6 and cover idempotency, stock underflow, failed-transfer rollback, two-office balance conservation, entitlement and capability enforcement, user/installation geographic isolation, route guards, scoped office lookup, actual Blade dashboard rendering and safe CSV content. The isolated multiprocess MariaDB rehearsal verifies simultaneous overspending prevention, idempotent adjustment and fulfilment retries, opposite transfers, cancellation-versus-fulfilment and audit reconciliation using 10 actual worker processes. Existing CI now runs this rehearsal against its MySQL/MariaDB matrix. Browser interaction, installer/upgrade rehearsals and paired payment activation still need validation before release. This does not claim those checks passed.

Remaining commercial/full-scope limitations: no public storefront or checkout (this module is internal campaign distribution); dashboard alerts rather than background low-stock email; one polling unit per office; no multi-step dispatch/receipt, partial fulfilment; no valuation/cost accounting; no opening-balance import. Catalogue creation and distribution are functional, but this increment does not establish the complete release acceptance criteria. Authoritative Portal pricing, signing identity, SMS wallet state and existing release assets remain untouched.


Expanded scope regressions cover all five licensed packages, national/state/senatorial/federal/LGA/ward/polling-unit user boundaries and missing jurisdiction. A targeted existing scope-service correction includes legacy polling units with NULL constituency fields through their ward/LGA relationship, while refusing to override conflicting explicit constituency IDs. The inventory plus existing licence/agent scope regression batch passes 43 tests (81 assertions) on SQLite.

Pending requests may be cancelled by their requester or an authorized fulfiller with jurisdiction over both offices. Requested, fulfilled and cancelled events append to an independent immutable request audit. Fulfilled requests cannot be cancelled; cancelled requests cannot be fulfilled. Stock movement history remains append-only.


Inventory schema initialization guards each table independently. A dedicated interrupted-migration regression preserves category/material, stock, request-event and movement records through repeated migration execution and recreation of the last missing table. The rehearsal uses disposable test schemas and does not invoke retained-data production rollback methods.
