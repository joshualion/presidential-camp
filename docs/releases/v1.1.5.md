# Campaign Manager v1.1.5

Automatic updates check server readiness and active update coverage before downloading the application archive. Installations without coverage continue to secure Portal checkout; free manual downloads remain available on GitHub.

Database backups select a consistent transaction snapshot for InnoDB or application-table READ locks for supported mixed engines, including MyISAM, MEMORY and MariaDB Aria. Engines are preserved. Missing or failed native dump/import tools select a streaming PDO backup and recovery format automatically. Incomplete exports are discarded and retried from a fresh snapshot.

Failed migrations and health checks attempt automatic restoration of verified database and application backups. An independent supervisor handles interrupted workers; separate command leases prevent recovery racing a surviving migration. Maintenance is released only after recovery succeeds. Backups remain private.

## Existing installations

The included signed updater bootstrap updates the updater used by versions 1.0.8 through 1.1.4. Existing updater code cannot gain the new payment and backup behavior just by discovering this release. Install the verified bootstrap once, then use its Automatic Update screen. See docs/coverage-first-updates.md.

No database reset, engine conversion, or seeding is part of the update.

## Release verification

Publication is blocked pending application tests on PHP 8.2/8.3, native/PDO backup and restore checks on MySQL 8 and MariaDB 10.11/11.4, and signed upgrades using both the official 1.1.3 and 1.1.4 archives with the new bootstrap. Entitlement calls in isolated upgrade rehearsals are stubbed; real payment and the owner's production installation require separate verification.

Readiness cannot override denied hosting permissions, corruption or exhausted storage. Unsupported remote/discarding engines, active database events, external forced workers and unsupported connection topologies remain explicit compatibility limits.
