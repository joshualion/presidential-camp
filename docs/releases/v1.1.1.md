# Campaign Manager v1.1.1

Campaign Manager UI improvements and optional safe automatic updating. Existing campaign data, installation identity, configuration and uploads are preserved.

- Official Updates discovers new stable releases and shows the next relevant action: verify the package, complete payment when needed, or update safely.
- Optional automatic updating uses Portal-configured service prices by campaign scope, per installation and target release. Manual GitHub downloads remain free; the service creates no subscription or application licence.
- Automatic updates verify signed package policies, create private database/file backups, run only reviewed pending migrations and check application health before reopening the installation. Failed attempts retain the same purchase for retry.
- A signed bootstrap companion connects supported 1.0.8, 1.0.9 and 1.1.0 installations that lack the new updater. Unsupported/customized installations require compatibility review or manual updating.
- Installation registration and contact preferences live in Settings. The updater page keeps registration administration out of the main update flow.
- Server access confirmation and installer screens use consistent branding, accessible validation and mobile layouts.

## Installing this update

Manual updating remains available through the official release ZIP. Preserve `.env`, uploads and installation state, back up the application and database, and run only the required pending migrations. Preparing a package alone does not apply it.

For the automatic service, complete the one-time installation registration/contact confirmation, prepare the package and pass server checks before purchasing. After confirmed payment, start the update explicitly. Hosts need compatible PHP CLI/process execution, file permissions, database backup clients and sufficient disk capacity. Interrupted migrations leave maintenance enabled and verified backups available for operator recovery. See [automatic update operations](../automatic-updates.md).

The Portal logo, order display, installation reporting, support and checkout changes deploy from the separate private Portal repository.

## Publication

Publish only after authorized CI validation and merge, Portal migration deployment, scope pricing and matching payment configuration and end-to-end payment verification. Use the established signing identity. Assets are `campaign-manager.zip`, `campaign-manager.zip.sha256`, `release-manifest.json`, `campaign-manager-updater-bootstrap.zip` and its SHA-256 file. Preserve the existing immutable v1.1.0 release.
