# Campaign Manager v1.1.2

Fixes update discovery for existing installations and includes time-based automatic-update coverage.

- Small signed public metadata stays below the original 1 MiB checker limit. The full signed file checksums remain inside the ZIP, bound by their exact signed manifest hash.
- The checker also accepts bounded larger legacy metadata without weakening signature verification.
- One Portal payment covers all automatic updates during the purchased coverage period for the same registered installation and campaign scope. The default is 12 calendar months, with no automatic renewal. The Portal owner can change the duration for future purchases; existing purchases retain their agreed period. Original target-release retries remain available.
- Existing verified automatic-update purchases receive the same default period from their original payment date. Refunds and cancelled payments do not authorize future updates. Free manual downloads remain available.
- The signed bootstrap supports 1.0.8, 1.0.9, 1.1.0 and 1.1.1. Older installations without the engine, and 1.1.1 installations using the previous manifest policy, should install this release's bootstrap once before applying the automatic update. This does not reset the database.

Preserve configuration, uploads and installation identity. Compatible hosts receive private backups and only explicitly reviewed pending migrations. No fresh migrations, database wipes or seeders run during an update. See the packaged automatic-update operations guide for requirements and recovery.
