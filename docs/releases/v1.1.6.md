# Campaign Manager v1.1.6

This cumulative release fixes an older downloaded update hiding or blocking the latest release. It includes every change in 1.1.4 and 1.1.5, including coverage-first automatic updates and engine-aware database backup and recovery.

- Official Updates shows the latest discovery result ahead of an older prepared package.
- Automatic Update refreshes signed metadata, checks readiness and coverage, and rechecks the exact reviewed version and checksum before downloading or reusing a package.
- After coverage is confirmed, older unused downloads are replaced automatically. A matching verified package is reused. Active updates, pending recovery and private backups stay protected.
- Availability is recalculated against the installed version after an update.
- Direct upgrades from 1.1.3, 1.1.4 and 1.1.5 are supported. Install the signed 1.1.6 updater bootstrap once on an existing older installation; publishing a release cannot change its already-installed updater.

## Existing installations

Follow the [automatic update guide](https://github.com/joshualion/Campaign-Manager/blob/main/docs/automatic-updates.md). Download the bootstrap ZIP and checksum from this release into a private server directory, verify the checksum, extract it, and run `php bootstrap-install.php /absolute/path/to/existing/core`. If a previous bootstrap exists, use `--replace-bootstrap`; replacement refuses an active update or unrecovered job. Sign in as Super Admin and open `/campaign-update-bootstrap.php` for the new flow. Your installed version stays unchanged until the update completes.

Official manual software downloads remain free. In-app archive downloads require valid automatic-update coverage. Hosts must support the required permissions, private storage, available disk space and consistent backups. A failed safety check stops before application changes; it never silently skips the backup.

## Validation

Publication requires PHP 8.2/8.3 application checks, the MySQL/MariaDB backup matrix, signature and checksum verification, and isolated direct upgrade rehearsals using the official 1.1.3, 1.1.4 and 1.1.5 archives. The rehearsals include an obsolete 1.1.4 stage and verify package reuse, backups, migrations, existing users, credentials, environment and uploads. Entitlement is stubbed in isolated rehearsals; this is not a live customer payment test.
