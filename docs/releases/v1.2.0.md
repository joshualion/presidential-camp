# Campaign Manager v1.2.0

Secure registration confirmation returns resolve the verified installation domain and resume Official Updates through normal login. Confirmation alone never grants update access, starts payment or installs an update.

Super Admins can create reusable roles, assign independent module and action permissions, and inspect user grants and restrictions. Administrative levels, licensed features and geographical boundaries continue to apply. Existing customer roles and assignments remain intact until explicitly adopted into managed capabilities.

Incident reporting now stores validated evidence on private storage and serves it through authorized routes. Images and supported videos have previews and downloads, with clear missing-file status. Super Admins control allowed media, size and count limits; disabling new uploads preserves historical access.

## Upgrade and operations

Two additive migrations introduce managed permission metadata and incident evidence metadata. Existing assignments, election results and incidents are preserved. No destructive rollback or reseeding is performed. Upgrades from 1.1.3 through 1.1.9 are rehearsed with the established signed bootstrap, private backups and explicit installation consent.

The paired Portal registration-status and domain-binding contract must be deployed before this release. See `docs/development/v1.2.0-development-report.md` and Portal `docs/engineering/verification-return-contract.md`.

Historical public evidence should be migrated using `php artisan campaign:incident-evidence:privatize` first in dry-run mode. After a verified backup and review, `--apply` copies and verifies files; `--apply --remove-public` removes only verified public originals. New evidence is private immediately.
