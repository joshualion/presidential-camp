# Phase 2C Scope Enforcement Route Audit

Date: 2026-06-17

## Scope

This audit covers Campaign Manager core app read-path leakage risks before location data provisioning.

Reviewed route families:

- `/dashboard` and role dashboard routes
- `*/dashboard/stats`
- role-specific location dashboard drilldowns
- member list/data/detail routes
- election operations center routes
- election result report, export, chart, and collation routes
- incident and evidence routes
- chart/statistic endpoints
- AJAX member/location/recipient endpoints
- bulk SMS and direct messaging recipient endpoints
- location import/export routes
- admin license and installer diagnostic routes

## Covered By Central Services

`LocationScopeService`

- Applies role boundary scope and then local licensed scope.
- Covered subjects include users/members, polling units, wards, LGAs, votes, incidents, and polling unit results.
- Used by dashboard metrics, member lists, election reports, operations center, AJAX member data, agent location selectors, and SMS recipient counts.

`LicensedScopeQueryService`

- Applies local license constraints for self-hosted active licenses.
- No-op in managed mode and in self-hosted missing-license/uninstalled state.
- Used directly for chart UUID guards, dashboard drilldown guards, messaging recipients, bulk SMS, notification recipients, imports, location reads, member/detail guards, result/incident/evidence guards, and write payload validation.

`StructuralLocationAccessService`

- Covers structural geography list/read scoping for locations.

## Remaining Risks

- Some legacy role dashboard views still receive legacy scalar variables alongside the scoped `dashboardMetrics` payload. The detail routes are guarded and main stat cards are scoped, but Phase 2D/2E should retire the duplicate scalar dashboard variables to avoid view drift.
- Community/social feed routes are not geographically scoped in this phase. They are not campaign geography reports, but they may need separate product-level privacy rules later.
- Support groups are global because `support_groups` has no boundary columns. Recipient and member actions involving users are scoped, but group records themselves are not geography-bound.
- Permission, role, age grade, religion, and political party management routes are global configuration records and are intentionally not scoped by geography.
- Election records themselves are global campaign objects; report/result rows under elections are scoped.
